# Bugfix: 用户侧写生成问题修复

## 修复记录

- **2025-01-22 12:30**: 修复用户侧写生成 prompt
- **2025-01-22 13:00**: 修改为每次对话都更新侧写（原来是每5次）

## 问题描述

用户侧写文件（`用户侧写.md`）生成的格式不正确，包含的是 AI 的分析思考过程，而不是最终的侧写文档。

### 错误示例

```markdown
Let me analyze this task:

1. The user wants me to analyze 5 recent inputs...
2. The 5 inputs are:
   - "今天东莞气温"
   - "小米股价"
   ...

Action plan:
- Create a user_profile.md file with the analysis
- Keep it concise (100-200 words)

Let me structure the response according to the JSON format required.
```

### 期望格式

```markdown
# 用户侧写

## 语言偏好
中文

## 交流风格
简洁直接，偏好技术性回答

## 技术偏好
TypeScript, Node.js

## 其他特征
重视代码质量，喜欢实用示例
```

## 根本原因

AI 将"生成用户侧写"任务误解为需要输出分析过程的任务，而不是直接输出结果。原 prompt 没有明确禁止输出思考过程。

## 解决方案

### 修改文件
- `src/repl.ts` 的 `callAIForProfile()` 方法（第 2872-2939 行）

### 关键改进

1. **明确角色定位**
   ```
   你是一个用户侧写分析专家。
   ```

2. **禁止分析过程**
   ```
   【重要】
   - 直接输出侧写文档，不要输出任何分析过程、思考步骤或说明
   - 不要说"让我分析"、"我将生成"之类的话
   - 直接开始输出侧写内容
   ```

3. **提供输出示例**
   ```
   【输出格式示例】
   # 用户侧写

   ## 语言偏好
   中文

   ...
   ```

4. **结构化要求**
   - 使用【任务】【重要】【要求】等标记
   - 清晰的编号列表
   - 明确的格式说明

## 对比分析

```
侧写应包含：
```

```
你是一个用户侧写分析专家。

【任务】请生成用户侧写文档，直接以markdown格式输出。

【重要】
- 直接输出侧写文档，不要输出任何分析过程、思考步骤或说明
- 不要说"让我分析"、"我将生成"之类的话
- 直接开始输出侧写内容

【输出格式示例】
# 用户侧写

## 语言偏好
中文

## 交流风格
简洁直接，偏好技术性回答

## 技术偏好
TypeScript, Node.js

## 其他特征
重视代码质量，喜欢实用示例

【要求】
1. 提取用户语言偏好（中文、英文等）
2. 识别交流风格（简洁、详细、正式、随意等）
3. 识别技术偏好（编程语言、工具偏好）
4. 输出简洁（100-200字）的markdown文档
5. 直接输出内容，不要有分析过程
```

**优势**：
- ✅ 明确的角色定位
- ✅ 明确禁止分析过程
- ✅ 提供清晰的输出示例
- ✅ 结构化指令，易于遵循
- ✅ 多次强调"直接输出"

## 经验总结

1. **明确性是关键**
   - AI 需要非常明确的指令才能避免输出不必要的内容
   - "不要做 X" 和 "要做 Y" 都需要明确说明

2. **示例很重要**
   - 提供输出格式示例可以大幅提高输出质量
   - 示例比文字描述更直观

3. **角色定位**
   - 给 AI 一个明确的角色（专家身份）可以提高输出质量
   - 角色定位帮助 AI 理解任务的专业性和期望

4. **结构化指令**
   - 使用【标记】、编号列表等方式组织 prompt
   - 使指令层次清晰，易于理解和遵循

5. **多次强调**
   - 重要指令需要在多个地方重复强调
   - "直接输出"在 prompt 中出现了 3 次

## 修改 2：每次对话都更新侧写

### 修改内容
将 `PROFILE_UPDATE_INTERVAL` 从 `5` 改为 `1`，实现每次对话后都更新用户侧写。

### 修改位置
- 文件：`src/session.ts` 第 31 行
- 修改前：`private readonly PROFILE_UPDATE_INTERVAL = 5;`
- 修改后：`private readonly PROFILE_UPDATE_INTERVAL = 1;`

### 影响

**优点**：
- ✅ 侧写实时更新，更准确反映用户偏好
- ✅ AI 能够更快适应用户的语言和风格变化
- ✅ 每次对话都能从最新的侧写中受益

**缺点**：
- ⚠️ API 调用增加：每次对话后都会调用 AI 生成侧写
- ⚠️ 时间开销：每次对话多等待 2-5 秒（生成侧写的时间）
- ⚠️ 侧写频繁变化：可能导致侧写不够稳定

### 性能评估

假设每次对话：
- 原来的 API 调用：1 次（对话） + 每 5 次对话额外 1 次（侧写） = 平均 1.2 次/对话
- 现在的 API 调用：1 次（对话） + 1 次（侧写）= 2 次/对话

**API 调用增加：约 67%**
**时间开销：每次对话增加 2-5 秒**

### 后续优化建议

如果发现性能开销太大，可以考虑：

1. **智能更新策略**
   - 只在用户输入内容显著不同时更新
   - 检测语言/风格变化才更新

2. **后台更新**
   - 异步更新侧写，不阻塞对话
   - 显示"更新中..."提示，继续对话

3. **可配置间隔**
   - 允许用户自定义更新间隔（1/3/5/10）
   - 根据项目需求调整
