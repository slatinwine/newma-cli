# `/init` Command - Project Initialization

## Overview

The `/init` command is a new feature that initializes the AI's understanding of your project by analyzing its structure and generating a comprehensive summary that is saved to `KODE.md`.

## Usage

```bash
# Start interactive mode
npx newma-cli -i

# Run the init command
[newma] ❯ /init
```

## What It Does

1. **Scans All Project Files**: Analyzes entire project structure in batches
   - First gets complete file list
   - Filters out unnecessary directories (node_modules, .git, dist, etc.)
   - Scans in batches of 5 files with content (first 200 lines each)
   - Shows real-time progress for each batch

2. **Generates Summary**: Creates a comprehensive overview including:
   - Project Overview (purpose, what it does)
   - Tech Stack (languages, frameworks, dependencies)
   - Architecture (structure, main components)
   - Key Files (important files and their purposes)
   - Development Guide (how to run, test, build)
   - Important Notes (conventions, patterns, considerations)

3. **Saves to KODE.md**: Writes the summary as markdown in your project root

## KODE.md Format

The generated `KODE.md` file includes:

```markdown
# KODE.md

> **Last Updated**: 2025-01-18T10:30:00.000Z
>
> This file contains the AI's understanding of this project.

---

# Project Overview

[Generated summary content...]

---

*This file is automatically generated by the `/init` command. You can edit it manually to add additional context or corrections.*
```

## Integration with Other Features

- **User Profile**: Respects your language preference and communication style
- **Session History**: Can be used alongside `# memorize` command
- **Auto-update**: You can re-run `/init` anytime to update the summary

## Technical Details

- **Scanning**: Uses `scanDirectory()` with `listOnly: false, maxFiles: 20`
- **AI Analysis**: Calls AI in 'plan' mode with structured prompt
- **File Writing**: Creates or overwrites `KODE.md` with timestamped content
- **Cancellation**: Supports Ctrl+C to cancel mid-operation

## Best Practices

1. **Run `/init` when**:
   - Starting to work on a new project
   - After major architectural changes
   - When AI responses seem to lack project context

2. **Edit KODE.md manually** to add:
   - Domain-specific knowledge
   - Business rules
   - Team conventions
   - Important constraints

3. **Keep KODE.md in sync**:
   - Re-run `/init` after significant changes
   - Commit `KODE.md` to version control
   - Share with team for consistent AI understanding

## Future Enhancements

Potential improvements:
- `/init --deep` for more detailed analysis (more files)
- `/init --merge` to update existing summary without overwriting
- `/init --section <name>` to regenerate specific sections only
- Auto-detect when to suggest running `/init`
