# Chat 模式消息重复功能改进

> **⚠️ 功能已移除** (2026-01-24)
>
> **移除原因**: 用户要求移除消息重复逻辑
> **移除版本**: v3.2.0+
> **修改文件**: `src/ai.ts` (第 324-331 行, 346-348 行)
> **当前状态**: ❌ 已废弃，不再发送重复消息
>
> 移除前，聊天模式会向 AI 发送两遍相同的用户消息。移除后，只发送一遍。

---

## [历史文档] 改进概述

**实施日期**: 2026-01-18
**版本**: v3.1.0+
**影响范围**: Chat 模式（交互聊天）
**类型**: 功能增强（已移除）

### 背景

研究表明，对于 AI 聊天模式，重复用户输入可以提升 AI 响应的准确率。用户希望在 Newma (牛码) 的 chat 模式中添加类似功能：将用户输入复制两遍发送给 AI，但界面上仍然只显示一遍。

### 需求

- ✅ **AI 侧**: 收到两遍相同的用户输入
- ✅ **UI 侧**: 界面显示仍然只有一遍
- ✅ **向后兼容**: 不影响其他模式（plan、verify 等）

---

## 实施方案

### 修改位置

**文件**: `src/ai.ts`
**函数**: `chatAI()`
**行数**: 214-215

### 代码变更

```typescript
// 修改前
messages: [
  {
    role: 'system',
    content: systemPrompt
  },
  { role: 'user', content: userMessage },
]

// 修改后
messages: [
  {
    role: 'system',
    content: systemPrompt
  },
  { role: 'user', content: userMessage },
  { role: 'user', content: userMessage },  // ← 新增：重复用户消息
]
```

### 工作原理

1. **用户输入** → REPL 捕获
2. **记录到会话** → 保存原始输入（一遍）
3. **调用 chatAI()** → 发送两遍消息给 AI
4. **AI 响应** → 处理后返回
5. **UI 显示** → 显示一遍（用户感知不到变化）

## 设计决策

### 1. 为什么在 `chatAI()` 中修改？

**理由**:
- ✅ 集中修改，一处修改影响所有调用点
- ✅ 不影响调用方的代码
- ✅ 易于维护和回滚

**替代方案**:
- 在调用方修改（如 `repl.ts`）
  - ❌ 需要修改多处
  - ❌ 容易遗漏某些调用点

### 2. 为什么不是可选功能？

**当前实现**: 强制开启
**理由**:
- ✅ 简单直接，无需配置
- ✅ 根据研究，重复输入总是有益的
- ✅ 不会造成负面影响（只是多发送一次相同消息）

**未来改进**: 可以添加可选开关
```typescript
// 未来可能的实现
const duplicateMessage = config.chat?.duplicateMessage ?? true;
messages: [
  { role: 'system', content: systemPrompt },
  { role: 'user', content: userMessage },
  ...(duplicateMessage ? [{ role: 'user', content: userMessage }] : [])
]
```

### 3. 为什么不影响 UI？

**原因**:
- UI 显示的逻辑在 `chatMode()` 中（`src/repl.ts:1485`）
- `chatAI()` 只负责与 AI 通信，不负责显示
- 会话历史中保存的是原始输入（一遍）

## 性能影响

### Token 消耗

**影响**:
- 每次聊天请求增加 `len(userMessage)` tokens
- 示例：用户输入 50 tokens → 实际发送 100 tokens

**成本**:
- 增加约 1 倍用户输入的 token 消耗
- 对整体成本影响较小（系统 prompt 和响应通常更大）

### 响应时间

**影响**:
- API 调用时间基本不变（网络传输差异可忽略）
- AI 处理时间可能略微增加（输入变长）

**结论**: ✅ 性能影响可忽略不计
