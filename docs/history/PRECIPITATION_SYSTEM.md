# Precipitation System - Technical Documentation

## Overview

The **Precipitation System** (经验沉淀系统) is an automated AI-driven system that continuously learns from the Newma memory systems and converts experiences into reusable skills. It runs on a scheduled basis (default: daily at 2 AM), analyzes patterns across 7 memory systems, and generates skill drafts for user approval.

### 5. PrecipitationCoordinator (`src/memory/precipitation-coordinator.ts`)

**Responsibility**: Orchestrate all components and manage precipitation workflow

**Key Features**:
- Component lifecycle management
- End-to-end precipitation workflow
- Status tracking and reporting
- Error handling and recovery

**Workflow**:
```
1. Initialize (start())
   ├─ Create draft directory structure
   ├─ Initialize scheduler
   └─ Schedule first precipitation

2. Scheduled Execution (every 2 AM by default)
   ├─ Analyze memories
   ├─ Generate suggestions
   ├─ Filter by confidence
   ├─ Auto-approve/reject (optional)
   ├─ Generate skill files
   └─ Cleanup old drafts

3. Manual Trigger (trigger())
   └─ Execute precipitation on demand

4. Query Status (getStatus())
   └─ Get scheduler status, draft stats, config
```

**Configuration**:
```typescript
interface PrecipitationConfig {

  autoApproveBelow?: number; // Auto-approve if confidence >
  autoRejectAbove?: number; // Auto-reject if confidence <
  analysisDays?: number; // Days to look back, Default: 7
}
```

**Methods**:
- `start()` - Start coordinator
- `stop()` - Stop coordinator
- `trigger()` - Manually trigger precipitation
- `getStatus()` - Get system status

## Error Handling

### Retry Logic

**Scheduler Retry**:
```typescript
private async executePrecipitation(callback: () => Promise<void>): Promise<void> {
  const maxRetries = 3;
  let attempt = 0;

  while (attempt < maxRetries) {
    try {
      await callback();
      return; // Success
    } catch (error) {
      attempt++;
      if (attempt >= maxRetries) {
        console.error('[Scheduler] Max retries reached');
        throw error;
      }
      const delay = Math.pow(2, attempt) * 1000; // Exponential backoff
      await new Promise(resolve => setTimeout(resolve, delay));
    }
  }
}
```

### Graceful Degradation

**Missing Memory System**: If a memory system is unavailable, log warning but continue with others

**AI API Failure**: Return empty suggestions, don't crash scheduler

**File System Errors**: Log error, skip current operation, continue with others

## Performance Considerations

### API Usage

**Per Precipitation**:
- 1-2 API calls (analysis only)
- 5,000-10,000 tokens (depends on memory size)
- 30-60 seconds execution time

**Daily Cost**: ~$0.01-0.02 (with gpt-4o-mini)

### Optimization Strategies

1. **Limit Analysis Window**: Use `analysisDays` to limit data scanned
2. **Confidence Threshold**: Filter out low-quality patterns early
3. **Max Skills Limit**: Prevent excessive skill generation
4. **Incremental Analysis**: Only analyze new data since last run (future)

## Troubleshooting

### Scheduler Not Running

**Symptom**: `/precipitation-status` shows "Stopped"

**Solutions**:
1. Check `enabled: true` in settings.json
2. Verify cron expression format
3. Check system clock/timezone

### No Skills Generated

**Symptom**: Precipitation runs but generates 0 skills

**Solutions**:
1. Lower `confidenceThreshold` (try 0.4)
2. Increase `analysisDays` to scan more data
3. Check OPENAI_API_KEY is valid
4. Verify memory systems have data

### Drafts Not Appearing

**Symptom**: `/drafts` shows no drafts after precipitation

**Solutions**:
1. Check `.kode/skills/drafts/` directory exists
2. Verify file permissions
3. Check precipitation logs for errors
